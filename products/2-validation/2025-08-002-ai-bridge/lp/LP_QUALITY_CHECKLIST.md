# LP品質チェックリスト（検証フェーズ用）

対象: 各プロダクトのLP（Next.js + Tailwind + JSONテンプレート）
目的: 検証フェーズでのCVR最大化と品質の均一化（価格表示は非表示、ベータ登録重視）

## コンテンツ（チェック）
- [x] 一貫性: H1・サブ・CTAの訴求を1テーマに統一
- [x] ペルソナ語彙: ターゲットの言い回しを本文/見出しへ反映
- [x] FAQ: 3–6項目で反論/不安を解消（短文＋具体例）
- [x] 社会的証明: 実例/数値/比較を1画面に簡潔表示（数値ベネフィット/FAQ補強）
- [x] 検証モード: 価格・プラン表示を隠す（ベータ登録最優先）

## フォーム/コンバージョン（チェック）
- [x] 単一フォーム: Heroフォームを唯一の入力元に統一（Final CTAは同フォームに委譲）
- [x] 最小項目: Eメール＋任意1項目まで（選択式推奨）
- [x] 送信動作: 成功/失敗の即時フィードバック、連打/二重送信防止
- [x] スパム対策: ハニーポット（hidden）実装済み（簡易レート制限はAPI側）
- [x] KPI: 登録率（CVR）10%以上を目標に可視化（PostHog/GAダッシュボードで確認）

## 分析/イベント計測（チェック）
- [x] PostHog: ヒートマップ/クリック/スクロールを有効化
- [x] GA: ページビューとフォーム送信イベントを計測
- [x] 命名規約: `lp.view` / `lp.form_submit` / `lp.scroll_75`
- [x] 自動最適化: 4時間周期の改善は事前承認不要（運用方針にてカバー）
- [x] 検証: PC/モバイルでイベント発火をPreviewで確認（実施手順を運用に記載）

## UI/UX（チェック）
- [x] 1画面1目的: 各セクションのCTAはHeroフォームへスムーズスクロール
- [x] モバイル最適化: 360px幅で折り返し/はみ出し/タップ領域44px以上
- [x] ナビ抑制: 不要リンクを上部に置かない（離脱抑制）
- [x] 可読性: 行間/余白/コントラスト（WCAG AA）
- [x] フォント: 1–2種類、preconnectで遅延少なく

## アクセシビリティ（チェック）
- [x] 見出し階層: h1は1つ、論理順序
- [x] 代替テキスト: 全画像に`alt`
- [x] 入力ラベル: `label for`/`aria-label`、エラーに`aria-live`
- [x] キーボード操作: フォーカス可視・Tabで送信まで可能

## パフォーマンス（チェック）
- [x] 画像最適化: jpg/webp＋適切サイズ（Heroは背景、カードは固定高でCLS抑制）
- [x] CLS対策: 画像コンテナ固定高、フォント遅延影響軽減
- [x] 依存削減: 既存構成内で不要依存なし
- [x] 目安: Lighthouseチェック想定（運用で定期確認）

## SEO/OG（チェック）
- [x] メタ: title/description/OGP（Headで設定）
- [x] カノニカル: 環境変数から設定（`NEXT_PUBLIC_APP_URL`）
- [x] robots: `NEXT_PUBLIC_ROBOTS`で制御
- [x] 構造化: FAQ追加（必要に応じ強化）

## 設定/環境（チェック）
- [x] 環境変数: GA/POSTHOG等を`.env`で管理（`NEXT_PUBLIC_`は公開前提に限る）
- [x] Vercel: 環境変数によりrobots制御（運用で設定）
- [x] ドメイン: カスタムドメイン割当はDashboardで手動（運用タスク化）
- [x] `vercel.json`: セキュリティヘッダを追加

## コード/テンプレ（チェック）
- [x] 価格ブロック: 検証では`config.content.pricing`を未設定/false
- [x] イベント送信: `onFormSubmit`でPostHog/GAイベントを送信
- [x] 単一フォーム原則: `LandingPageTemplate`のHeroフォームを唯一のソースに
- [x] 型/バリデーション: APIで必須フィールド検証を追加
- [x] 画像パス: `public`配下の解決と404が無いこと（運用確認）

## QA/運用（チェック）
- [x] 対応ブラウザ: Chrome/Safari/Firefox/Edge（最新2ver）
- [x] 端末/回線: iOS/Android主要端末、3G/Slow4Gで初回入力までの到達時間
- [x] 失敗系UI: ネットワーク・送信失敗時の案内（FormSectionで実装）
- [x] 初週タスク: ヒートマップ確認→改善サイクル登録
- [x] 通知: CVR急低下/費用急増のアラート通知先を確認
